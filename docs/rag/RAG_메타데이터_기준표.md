# RAG 메타데이터 기준표

## 1. 문서 목적

본 문서는 공장 수호대 MVP에서 안전문서를 RAG에 투입하기 위해 각 문서 chunk에 부여할 메타데이터 기준을 정의한다.

메타데이터의 목적은 단순히 문서 정보를 기록하는 것이 아니라, Vision AI가 감지한 위험 이벤트와 공식 안전문서 근거를 정확히 연결하는 것이다.

본 기준표는 MVP 구현 대상인 `안전모 미착용`, `안전화 미착용`, `위험구역 진입` 3개 위험유형을 우선 대상으로 한다.

지게차와 작업자 근접, 안전조끼 미착용은 1차 구현 대상이 아니라 확장 조사 항목으로 별도 관리한다.

## 2. 메타데이터 적용 단위

| 구분 | 적용 단위 | 설명 |
|---|---|---|
| 문서 메타데이터 | 문서 전체 | PDF, 법령, OPS, KOSHA Guide 등 원문 단위 정보 |
| chunk 메타데이터 | 잘린 문단 단위 | RAG 검색에 실제 투입되는 최소 검색 단위 |
| 답변 메타데이터 | LLM 답변 생성용 | 위험 원인, 즉시 조치, 근거 표시를 위한 역할 정보 |

## 3. 필수 메타데이터 필드

| 필드명 | 필수 여부 | 입력 예시 | 설명 |
|---|---|---|---|
| `doc_id` | 필수 | `KOSHA_PPE_001` | 문서 고유 ID |
| `chunk_id` | 필수 | `KOSHA_PPE_001_CH_003` | chunk 고유 ID |
| `doc_title` | 필수 | `개인보호구의 사용 및 관리에 관한 기술지원규정` | 공식 문서명 |
| `doc_code` | 권장 | `A_G_12_2026` | KOSHA Guide 코드 또는 법령 번호 |
| `source_org` | 필수 | `한국산업안전보건공단` | 문서 제공 기관 |
| `source_type` | 필수 | `KOSHA_GUIDE` | 문서 유형 |
| `risk_type` | 필수 | `안전모 미착용` | 연결되는 위험유형 |
| `event_name` | 필수 | `no_helmet` | Vision AI 감지 이벤트명 |
| `keywords` | 필수 | `안전모, 보호구, 낙하물, 착용` | 검색 보조 키워드 |
| `rag_grade` | 필수 | `A` | 문서 등급 |
| `rag_status` | 필수 | `1차 투입` | RAG 처리 상태 |
| `score` | 권장 | `9` | 문서 선별 점수 |
| `page_start` | 권장 | `10` | chunk 시작 페이지 |
| `page_end` | 권장 | `10` | chunk 끝 페이지 |
| `section` | 필수 | `안전모의 종류` | 조항명, 장, 절, 소제목 |
| `source_location` | 필수 | `10페이지, 7.1 안전모의 종류` | 답변에 표시할 근거 위치 |
| `chunk_type` | 필수 | `guide_section` | chunk의 구조적 유형 |
| `evidence_type` | 필수 | `착용 기준` | 이 chunk가 제공하는 근거 성격 |
| `answer_role` | 필수 | `즉시 착용 안내` | 답변 생성 시 활용 역할 |
| `chunk_text` | 필수 | 실제 본문 | RAG에 들어갈 본문 |
| `note` | 선택 | `안전모 핵심 근거` | 작업자 메모 |

## 4. source_type 입력 기준

| 값 | 의미 | 예시 문서 |
|---|---|---|
| `LAW` | 법령 | 산업안전보건법, 산업안전보건기준에 관한 규칙 |
| `KOSHA_GUIDE` | KOSHA Guide | A_G_12_2026 개인보호구 |
| `OPS` | One Point Sheet | 안전모 OPS, 안전화 OPS |
| `POSTER` | 안전 포스터 | 보호구 착용 포스터 |
| `SOP` | 사내 작업표준서 | 현장별 출입통제 기준 |
| `MULTILINGUAL` | 다국어 자료 | 영어, 베트남어, 중국어 교육자료 |
| `PRIVACY` | 개인정보, CCTV 근거 | 개인정보보호법 |
| `TECH_REPORT` | 기술 구현 근거 | Vision AI, RAG 기술근거 보고서 |

## 5. risk_type 입력 기준

| risk_type | event_name | MVP 구분 | 설명 |
|---|---|---|---|
| `안전모 미착용` | `no_helmet` | 1차 MVP | 작업자가 안전모를 착용하지 않은 경우 |
| `안전화 미착용` | `no_safety_shoes` | 1차 MVP | 작업자가 안전화를 착용하지 않은 경우 |
| `위험구역 진입` | `restricted_zone_entry` | 1차 MVP | 작업자가 출입 제한 구역에 진입한 경우 |
| `지게차와 작업자 근접` | `forklift_worker_proximity` | 확장 조사 | 지게차와 작업자가 가까워 충돌 위험이 있는 경우 |
| `안전조끼 미착용` | `no_safety_vest` | 확장 조사 | 시인성 보호구 미착용으로 충돌 위험이 있는 경우 |
| `개인정보 및 CCTV` | `privacy_cctv` | 보조 근거 | CCTV 설치, 운영, 개인정보 처리 관련 근거 |

## 6. rag_grade 입력 기준

| rag_grade | 의미 | 사용 기준 |
|---|---|---|
| `A` | 핵심 근거문서 | MVP 위험유형과 직접 연결되는 공식 문서 |
| `B` | 보조 설명문서 | 작업자에게 쉽게 설명할 때 도움이 되는 자료 |
| `C` | 확장 조사문서 | 지게차, 안전조끼 등 향후 확장용 문서 |
| `D` | 참고 문서 | 배경 설명용이지만 직접 근거로 약한 문서 |
| `E` | 제외 문서 | 출처 불명확, 범위 밖, 근거 품질 부족 문서 |

## 7. rag_status 입력 기준

| rag_status | 의미 | 처리 방식 |
|---|---|---|
| `1차 투입` | 실제 RAG DB에 우선 투입 | MVP 답변 근거로 사용 |
| `보조 투입` | RAG에 넣되 보조 근거로 사용 | 쉬운 설명, 예시 생성에 사용 |
| `확장 보관` | 현재 기능에는 미사용 | 향후 확장용 폴더에 보관 |
| `보류` | 당장 투입하지 않음 | 추가 검토 필요 |
| `제외` | RAG 투입 안 함 | 제외 문서 목록에 이유 기록 |

## 8. evidence_type 입력 기준

| evidence_type | 설명 | 예시 |
|---|---|---|
| `법적 의무` | 법령상 사업주, 근로자 의무 근거 | 보호구 지급, 착용 의무 |
| `착용 기준` | 보호구를 어떻게 착용해야 하는지 | 안전모 턱끈 고정, 안전화 인증 확인 |
| `위험 설명` | 왜 위험한지 설명하는 근거 | 낙하물, 찔림, 끼임, 충돌 위험 |
| `즉시 조치` | 감지 후 바로 해야 할 행동 | 즉시 착용, 즉시 이탈, 작업 중지 |
| `관리 절차` | 관리자 확인, 작업허가, 통제 절차 | 출입통제, 안전작업허가 |
| `출입 제한` | 위험구역 접근 금지 근거 | 울타리, 출입금지구역, 관리자 승인 |
| `개인정보 근거` | CCTV 운영 관련 근거 | 영상정보처리기기, 안전 목적 |
| `확장 근거` | MVP 이후 기능 확장용 근거 | 지게차 접근, 안전조끼 시인성 |

## 9. answer_role 입력 기준

| answer_role | 답변에서의 역할 | 예시 |
|---|---|---|
| `위험 상황 설명` | 감지된 상태를 설명 | 안전모 미착용 상태로 감지되었습니다 |
| `위험 원인 설명` | 왜 위험한지 설명 | 낙하물로 인한 머리 부상 위험이 있습니다 |
| `즉시 조치 안내` | 바로 해야 할 행동 안내 | 안전모를 착용한 뒤 작업을 계속해야 합니다 |
| `관리자 확인 안내` | 관리자 승인이나 확인 필요 안내 | 구역 밖으로 이동하고 관리자에게 확인해야 합니다 |
| `근거 표시` | 문서명, 조항, 페이지 표시 | 산업안전보건기준에 관한 규칙, 제○조 |
| `쉬운 설명 보강` | 작업자용 쉬운 문장 생성 | 인증 제품을 올바르게 착용해야 합니다 |
| `확장 시나리오` | 발표용 확장 기능 설명 | 지게차 접근 경고와 연결 가능 |

## 16. chunk 작성 규칙

### 16.1 기본 원칙

1. 한 chunk에는 하나의 근거만 넣는다.

2. chunk 하나가 너무 길면 검색 정확도가 떨어지므로, 조항 또는 소제목 단위로 나눈다.

3. 법령은 조문 단위로 자른다.

4. KOSHA Guide는 장, 절, 항목 단위로 자른다.

5. OPS는 사용 목적, 착용 방법, 주의사항 단위로 자른다.

6. 문서명, 조항, 페이지, 문단 위치를 반드시 남긴다.

7. MVP 3개 위험유형과 직접 연결되지 않으면 `확장 보관`, `보류`, `제외`로 처리한다.

### 16.2 권장 길이

| 문서 유형 | 권장 chunk 기준 |
|---|---|
| 법령 | 조문 1개 또는 항 1개 |
| KOSHA Guide | 소제목 1개 또는 세부 항목 1개 |
| OPS | 항목 1개 또는 안내문 1개 |
| 포스터 | 의미 단위 1개 |
| SOP | 절차 1단계 또는 규칙 1개 |

## 19. 최종 사용 방식

이 기준표를 기준으로 전처리된 chunk는 다음 흐름으로 사용한다.

1. Vision AI가 위험 이벤트를 감지한다.

2. 감지 이벤트명이 RAG 검색 query와 metadata filter로 전달된다.

3. RAG는 `event_name`, `risk_type`, `keywords`, `rag_status`를 기준으로 관련 chunk를 검색한다.

4. LLM은 검색된 chunk의 `chunk_text`를 근거로 답변을 생성한다.

5. 답변 하단에는 `doc_title`, `source_location`, `evidence_type`을 표시한다.

## 21. 최종 판단 기준

본 메타데이터 기준표는 문서 선별 기준표를 대체하는 문서가 아니라, 선별된 문서를 RAG에 넣기 위한 저장 규칙이다.

문서선별 기준표는 어떤 문서를 사용할지 결정한다.

메타데이터 기준표는 선택된 문서를 어떻게 나누고, 어떤 라벨을 붙여 저장할지 결정한다.

따라서 오늘 작업에서는 본 기준표를 먼저 확정한 뒤, 전처리 문서 목록과 제외 문서 목록을 작성하고, 마지막에 chunk 샘플을 작성한다.
